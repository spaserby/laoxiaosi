## 写作风格规范（对齐系列既有篇章）

每篇统一遵循以下骨架，保证跨篇连贯：

1. **标题**：`【Spring AI 实战 DayN】主题：一句话副标题`（副标题点出本篇最大卖点）
2. **系列导航框**：开篇 `> 📌 系列说明` 引用块，列出全部章节并**加粗本文**，附 `> 📦 代码说明`
3. **问题驱动开篇**：先抛一个读者能感知的具体问题 / 实验，再引出技术方案
4. **原理与选型**：表格对比候选方案，讲清"为什么选它、不选别的"
5. **实现**：目录树标注新增文件（★）→ 关键代码 + 逐段讲解（代码只贴核心，不贴全量）
6. **踩坑备忘**：本篇真实踩过的坑，给出根因 + 修复（系列最有价值的部分）
7. **小结表**：`| 概念 | 一句话 |` 收尾
8. **下篇预告钩子**：留一个悬念问题引出下一篇

**篇幅**：正文 6~9 KB（深度转折点如 Day7/Day9/Day23 可放宽到 12 KB）；中文文件名，UTF-8 编码。

**跨篇呼应**：前篇埋伏笔、后篇回收（如 Day4 埋"确定性 ID"→ Day6 回收；Day7 留"模型可以不听"→ Day10 实锤）。

## 配图资产与渲染方法

**SVG → PNG 渲染**（三选一）：

```bash
# 方式一：浏览器截图（本仓库已验证的流程）
#   建一个临时 HTML：<body style="margin:0"><img src="xxx.svg" width="1280"></body>
#   浏览器打开后整页截图保存为 PNG

# 方式二：resvg（推荐，命令行无损）
resvg --width 1280 assets/day0-tech-stack-overview.svg assets/images/day0-tech-stack-overview.png

# 方式三：Inkscape / ImageMagick
inkscape xxx.svg -o xxx.png -w 1280
```

**SVG 设计规范**：画布宽 1280；中文字体族 `'Microsoft YaHei','PingFang SC','Noto Sans SC',sans-serif`；品牌主色藏青 `#1E3A8A`（呼应前端 V9 公报风）；分层用浅色底 + 深色边 + 白底卡片。

### 阶段一 · 流式对话内核（把"能聊天"做扎实）

**Day1 · SSE 流式聊天与停止生成**
- 核心问题：怎么让回复逐字蹦出，且点停止后**模型侧也中断**？
- 技术点：`Flux<ServerSentEvent>`、`Sinks.Empty` + `takeUntilOther`（Reactor cancel 传播）、SSE vs WebSocket vs 轮询选型、`[DONE]` 约定
- 配图：整体架构图（前端 → SSE → ChatClient.stream → 模型）
- 踩坑：Servlet 栈承载 WebFlux 响应的边界；停止信号跨实例传递

**Day2 · 会话记忆持久化**
- 核心问题：重启后为什么不能丢记忆？上下文越来越长怎么办？
- 技术点：Spring AI `ChatMemory` 接口、原文窗口 + 早期摘要两级压缩、会话隔离 conversationId
- 配图：两级压缩示意图（窗口滑动 + 摘要沉淀）
- 踩坑：记忆膨胀导致 token 超限；摘要时机选择

**Day16 · 思考过程可见化**
- 核心问题：推理模型的 reasoning_content 怎么透传给前端？
- 技术点：思考内容流式抽取、SSE `thinking` 事件、前端折叠面板
- 配图：SSE 七类事件时序图

**Day26 · 流式与滚动体验治理**
- 核心问题：长回答滚动跳动、停止后状态错乱怎么治？
- 技术点：滚动锚定判定、停止后前端状态机治理、缓冲平滑排空
- 配图：滚动锚定状态机

### 阶段二 · 工具调用（让模型会做事）

**Day3 · Function Calling 工具调用**

- 技术点：`@Tool` 注解、工具注册与描述、法律计算器（经济补偿金 / 加班费 / 诉讼时效 / 诉讼费）、参数自动绑定
- 配图：Function Calling 调用环（已有 SVG 可复用）

**Day8 · 框架升级与联网搜索**
